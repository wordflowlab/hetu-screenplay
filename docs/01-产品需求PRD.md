# 剧本创作产品需求

## 1. 产品定义

河图洛书的独立剧本创作插件，服务作者与外部Agent围绕持续积累的作品工作。作者表达目标、审阅完整成果与差异，Agent通过稳定CLI/MCP执行结构化操作；不要求作者掌握开发工具或重复填写对话内容。

## 2. 背景与第一性原理

创作的长期资产是作品、判断、来源和迭代历史。单次模型输出难以维护关联、处理并发和接续；固定的数据与确定性操作减少重复生成、上下文搬运和误改。生成成本降低后，版本、作者决定、局部返工及工程可恢复性仍有价值。规划是持续约束与候选，不等于已经发生的剧情或完成的制作。

## 3. 首版范围

原创、旧大纲、已有剧本、小说改编四类入口；可选全剧／季／集／段落／场次层级；人物弧线、关系、伏笔；复盘覆盖与未来提案区分；固定宿主分集及正文；Fountain起草返工交接；多备选、历史、比较、诊断及完整导出。

## 4. 作者决定

记录、保存、提交、选用、采纳及定稿分别处理。插件可保存Agent意见、未采用方案和外部工具回执，不自动使其成为正式正文、已选媒体、作者认可或已支付费用。作品读取范围不扩大为任意本机文件权。

## 5. 验收

通过隔离作品验证发现、安装、专业动作、核心回读、版本冲突、原键恢复、停用／重启用／卸载及相同数据的界面阅读。文学质量、真实影片审阅、平台发行和付费外发各自取证。

## 形成依据与第一性原理

创作工程同时包含内容、结构、证据和作者决定。一次性生成的网页、文本或画布能表达当下结果，却不能自行承担下一轮的身份、修订、比较和恢复。河图的价值在于使这些成果持续成为可读、可选择、可接续的作品。

模型能生成界面，不代表每次打开、切换和比较都应重新生成代码。Token成本、首屏延迟和生成不确定性，使常用阅读版式、确定性操作和专业校验适合由软件执行。复杂推理与具体内容由外部Agent负责；当模型更便宜、更快时，持久作品、来源、原操作和作者决定仍然必要，不能把产品价值仅定义为暂时的模型价格差。

通用宿主只保存创作事实与决定。专业方法、视图和结构随领域变化，由独立插件演进；插件通过稳定SDK复用核心能力，让新的专业实践无需反复修改宿主数据和导航。React阅读面、Markdown剧情、SVG关系图及时间线是按问题选择的表达，不要求作者学习编程或完成每项手工操作。

## 非功能要求

- 首次使用支持无上游作品、已有内容复盘和已有工程接续，不能依赖演示数据。
- 作品身份、固定来源、CAS与原操作由Core确定性执行；插件不能通过布局或提示词绕过。
- 同一专业动作在GUI与无窗口机器会话中执行同一应用用例；方法、Schema与运行包固定同一摘要。
- 全幅工作面隐藏宿主重复导航，保留单一返回；浅暗和窄窗均能阅读，键盘可定位。
- 可读、可解码、外部提供方声明与作者认可分别记录，实施状态以08与实际证据为准。
