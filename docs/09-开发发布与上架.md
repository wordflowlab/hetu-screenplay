# 开发、发布与上架

## 1. 本地开发

Node版本及命令以package.json为准。npm ci后依次check、test:unit、build、test:machine、test:ui；宿主源码由HETU_SOURCE指定，默认同级工作区相对位置。运行时仅使用打包产物，开发源码不进入插件安装目录。

## 2. 制品

dist包含plugin.json、backend.mjs、React工作面、Skill及引用、功能清单和许可证。无node_modules运行依赖，无Rust动态库，无独立MCP服务器；构建第三方许可清单与vendor来源摘要。

## 3. 安装与发现

用宿主实际发现的plugins.inspect_package核对包摘要，沿plugins.apply安装并回读，再通过原MCP连接发现能力和skills.read。停用不删作品数据，卸载保留专业历史；重装同包后回读。升级先核对格式，不静默迁移。

## 4. 发布与生态

在GitHub仓库发布固定版本包、摘要、许可证、功能清单与安装说明，按河图插件中心指南提交来源与制品。提交、Tag、Release及上架是独立操作，不能因本地包通过而宣称已公开发行。正式发布前验证陌生目录安装、升级与回退、目标平台运行及已有数据保持。

## 开发者维护合同

1. 修改功能先更新CAPABILITIES、包贡献Schema、领域不变量、用户用例与方法；宿主清单只维护发现入口，不复制专业动作。
2. 运行npm run check与单元测试，再构建独立dist。机器测试将包复制到隔离目录并固定摘要，避免源码重建影响同一验收中的安装包。
3. 使用真实稳定MCP覆盖全部专业动作、Skill资源、共享核心接续、CLI回读与安装生命周期；界面通过真实Electron同Core验证，不以mock页面替代。
4. 升级不兼容格式先定义迁移与回退边界；保留旧对象和原操作，不能用重新安装清空已有创作事实。
5. 发布时上传dist完整压缩包，提供固定版本与包摘要、LICENSE／THIRD_PARTY_NOTICES、CAPABILITIES和测试范围。GitHub负责源码和制品，插件中心登记可核验版本与下载入口；发现、安装和启用由河图负责。

插件包不是Codex插件包。安装后外部Agent仍通过现有河图连接动态发现，无需每次修改客户端配置；方法按Skill入口及resource读取。源码仓库变化不会自动替换用户已固定安装包。
